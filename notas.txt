Sobre React Query — tu intuición va bien encaminada, te la afino:

No es solo optimización de consultas — es un reemplazo completo de cómo manejás el estado de datos que vienen de un servidor. Hoy, sin React Query, cuando hacés una petición tenés que manejar manualmente:

- ¿Está cargando? → necesitarías un useState(loading)
- ¿Hubo error? → necesitarías un useState(error)
- ¿Los datos llegaron? → necesitarías un useState(data)
- ¿Necesito volver a pedir los mismos datos en otro componente? → tendrías que repetir todo esto

React Query te da todo eso ya resuelto, más:

- Cache automático (si ya pediste los proyectos, no los vuelve a pedir de la nada)
- Revalidación automática (si volvés a la pestaña, refresca datos viejos solo)
- Estados de loading/error listos para usar sin armarlos vos

export default function DashboardView() {
  // 3 estados separados que useQuery te da en 1 solo hook
  const [data, setData] = useState<Project[]>([]);
  const [isLoading, setIsLoading] = useState(true);
  const [isError, setIsError] = useState(false);

  useEffect(() => {
    // Función async DENTRO de useEffect (useEffect no puede ser async directamente)
    const fetchProjects = async () => {
      try {
        setIsLoading(true); // REACT-QUERY: LO TRAE HECHO isLoading
        const projects = await getProjects();//REACT-QUERY LO TRAE HECHO queryFn
        setData(projects); //REACT-QUERY LO TRAE HECHO data
      } catch (error) {
        setIsError(true);//REACT-QUERY LO TRAE HECHO error
      } finally {
        setIsLoading(false);
      }
    };

    fetchProjects();
  }, []); // ← array vacío = "ejecutá esto SOLO al montar el componente"//REACT-QUERY LO TRAE HECHO queryKey, parecido pero no tal cual-- 

  if (isLoading) return "cargando...";
  if (isError) return <p>Error al cargar</p>;
  
  return (/* JSX con data.map(...) */);
}
